## 1. Protocol & Identity (6 Features)
*Basic flow identification.*

| # | Feature | Extraction Details |
|---|---------|--------------------|
| 1 | `protocol` | **Logic**: <br>1. Check Ports: If src/dst port is 853 -> return `DOT`. If 53 -> return `TRADITIONAL`.<br>2. Check TLS: If it's port 443 AND has TLS Client Hello:<br>&nbsp;&nbsp;a. Parse SNI Extension.<br>&nbsp;&nbsp;b. Check `DoHServerDatabase` for SNI or DestIP.<br>&nbsp;&nbsp;c. If match found -> return `DOH`.<br>3. Else return `UNKNOWN`. |

## 2. Encrypted Traffic Analysis (6 Features - **NEW**)
*These features look inside the TLS flow without decrypting it.*

### 7. `large_packet_ratio`
*   **What it is**: The percentage of packets in the flow that are considered "Large" (> 600 bytes).
*   **Code Source**: `Flow.java` -> `largePacketCount`
*   **Extraction Step-by-Step**:
    1.  For every packet (sent or received), get its total length (Header + Payload).
    2.  Check: `if (length > 600) largePacketCount++`.
    3.  Finally: `getLargePacketRatio() = largePacketCount / (fwdCount + bwdCount)`.
*   **Why**: Large packets in DoH often correspond to full DNS responses (with certificates or large TXT records).

### 8. `medium_packet_ratio`
*   **What it is**: Percentage of "Medium" packets (400 - 600 bytes).
*   **Code Source**: `Flow.java` -> `mediumPacketCount`
*   **Extraction**:
    1.  Check: `if (length >= 400 && length <= 600) mediumPacketCount++`.
    2.  Calc: `mediumPacketCount / Total_Packets`.
*   **Why**: Typical size for a standard DoH query/response exchange.

### 9. `small_packet_ratio`
*   **What it is**: Percentage of "Small" packets (< 400 bytes).
*   **Code Source**: `Flow.java` -> `smallPacketCount`
*   **Extraction**:
    1.  Check: `if (length < 400) smallPacketCount++`.
    2.  Calc: `smallPacketCount / Total_Packets`.
*   **Why**: TCP ACKs, TLS Handshake fragments, or C2 "heartbeats".

### 10. `sni_entropy`
*   **What it is**: A measure of randomness in the Server Name (e.g., "google.com" vs "x8z9q2.net").
*   **Code Source**: `Flow.java` -> `extractSni()` -> `calculateShannonEntropy()`
*   **Extraction Step-by-Step**:
    1.  Wait for a packet with `ContentType = 0x16` (Handshake).
    2.  Parse bytes 5+ to find `HandshakeType = 0x01` (Client Hello).
    3.  Skip SessionID, CipherSuites, Compression to find **Extensions**.
    4.  Loop through extensions to find Type `0x0000` (Server Name).
    5.  Extract the string (e.g., "dns.google").
    6.  **Calculate**: `Entropy = -Sum(probability * log2(probability))` for each character.
*   **Range**: 0.0 (low randomness) to ~8.0 (high/random).

### 11. `is_known_doh_server`
*   **What it is**: Validates if we trust this server.
*   **Code Source**: `DoHServerDatabase.isKnownDoHServer()`
*   **Extraction**:
    1.  Get `sniHostname` (extracted above) and `dstIp`.
    2.  Check if `sniHostname` exists in `KNOWN_HOSTNAMES` (Set contains "dns.google", "cloudflare-dns.com", etc.).
    3.  Check if `dstIp` exists in `KNOWN_IPS` (Set contains "8.8.8.8", "1.1.1.1", etc.).
    4.  Return `1` if found, `0` otherwise.

### 12. `encrypted_payload_size_variance`
*   **What it is**: How much the size of the *encrypted data blocks* varies.
*   **Code Source**: `Flow.java` -> `tlsPayloadStats`
*   **Extraction Step-by-Step**:
    1.  Inspect TCP payload. Look for `ContentType = 0x17` (Application Data).
    2.  Read bytes 3-4 (Length field of the TLS record).
    3.  Add this length to a statistical tracker (`BasicStats`).
    4.  **Formula**: `Variance = Sum((x - mean)^2) / N`.

## 3. Traditional DNS Features (7 Features)
*Extracted via `DnsFeatureExtractor.java` (Port 53).*

### 13. `dns_amplification_factor`
*   **Formula**: `Total_Response_Bytes / Total_Query_Bytes`.
*   **Extraction**:
    1.  Parse DNS Header. If `QR=0` (Query), add packet size to `totalQueryBytes`.
    2.  If `QR=1` (Response), add packet size to `totalResponseBytes`.
    3.  Divide them.
*   **Meaning**: If I send 50 bytes and get 3000 bytes back, Factor = 60. This is an amplification attack.

### 14. `query_response_ratio`
*   **Formula**: `Total_Query_Packets / Total_Response_Packets`.
*   **Extraction**:
    1.  Count every DNS packet where `QR=0`.
    2.  Count every DNS packet where `QR=1`.
    3.  Divide.
*   **Meaning**: Normal is ~1.0. If 10,000 queries and 0 responses, Ratio = Infinity (Attack).

### 15. `dns_any_query_ratio`
*   **Formula**: `Count(Type==ANY) / Total_Queries`.
*   **Extraction**:
    1.  Parse DNS Question section.
    2.  Check `QType`. If `255` (ANY), increment `dnsAnyCount`.
    3.  Divide by total queries.

### 16. `dns_txt_query_ratio`
*   **Formula**: `Count(Type==TXT) / Total_Queries`.
*   **Extraction**:
    1.  Check `QType`. If `16` (TXT), increment `dnsTxtCount`.
    2.  Divide.

### 17. `dns_response_inconsistency`
*   **Formula**: `Abs(Total_Queries - Total_Responses)`.
*   **Meaning**: The simple numerical difference. 10 queries sent, 8 received -> Inconsistency = 2.

### 18. `dns_queries_per_second`
*   **Formula**: `Total_Query_Packets / Flow_Duration_Seconds`.
*   **Meaning**: The "speed" of the attack.

### 19. `port_53_traffic_ratio`
*   **Formula**: `(DNS_Query_Bytes + DNS_Resp_Bytes) / Total_Flow_Bytes`.
*   **Meaning**: How much of this flow was actually valid DNS? If 10%, it implies 90% was junk/non-DNS (Tunneling).

## 4. Flow Statistics & Rates (14 Features)
*Standard network metrics calculated in `Flow.java`.*

*   **20.** `flow_bytes_per_sec`: `Sum(All_Packet_Lens) / Duration_Sec`.
*   **21.** `flow_packets_per_sec`: `Count(All_Packets) / Duration_Sec`.
*   **22.** `fwd_packets_per_sec`: `Count(Src->Dst) / Duration_Sec`.
*   **23.** `bwd_packets_per_sec`: `Count(Dst->Src) / Duration_Sec`.
*   **24.** `flow_duration`: `Timestamp_Last_Packet - Timestamp_First_Packet` (in milliseconds).
*   **25-28.** `total_fwd/bwd_packets/bytes`: Simple counters incremented on every `addPacket` call.
*   **29-31.** `dns_total_queries/responses/bytes`: Aggregates passed from `DnsFeatureExtractor`.
*   **32-37.** `flow_iat_...` (Inter-Arrival Time):
    *   **Logic**: `Current_Packet_Time - Previous_Packet_Time`.
    *   Statistics (`Mean`, `Std`, `Min`, `Max`) are updated incrementally for every packet.

---

## 5. Packet Size Distribution (5 Features)
*   **38-39.** `fwd/bwd_packet_length_mean`: Average size of packets in each direction.
*   **40.** `packet_size_std`: Standard deviation of all packet sizes. (High std dev = variable traffic like web; Low std dev = constant size like audio/tunneling).
*   **41-42.** `flow_length_min/max`: Smallest and largest packet observed.

## 6. Advanced Features (2 Features)

### 43. `response_time_variance`
*   **Code Source**: `DnsFeatureExtractor` -> `pendingQueries` (Map)
*   **Extraction**:
    1.  When Query seen: Store `{TransactionID: Timestamp}` in a Map.
    2.  When Response seen: Find ID in Map. Calc `Diff = Now - StoredTime`.
    3.  Add `Diff` to statistics.
    4.  Calculate Variance of these diffs.

### 44. `average_packet_size`
*   **Formula**: `Total_Flow_Bytes / Total_Packet_Count`.
*   **Code Source**: `Flow.java` -> `flowLengthStats.getMean()`.
